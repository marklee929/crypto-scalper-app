# 2026-04-28 작업 서머리

## Heart Beat Coin Scalper 구조 기반 전략 리팩토링

### 목적
- 기존 단순 퍼센트 기반 진입/청산 구조를 구조 기반 상태 판별형 스캘퍼로 전환했다.
- 핵심 방향은 "싸졌기 때문에 매수"가 아니라 "구조가 살아 있을 때만 진입"이다.
- 진입보다 진입 금지 필터를 우선하도록 전략 흐름을 바꿨다.

### 주요 변경
- `core/market_structure.py` 신규 추가
  - 시장 상태 분류: `NO_TRADE`, `DEAD`, `FALLING`, `ACCUMULATION`, `HEARTBEAT`, `STRONG_HEARTBEAT`
  - 횡보 구분: `ACCUMULATION_SIDEWAYS`, `FALLING_SIDEWAYS`
  - 구조/거래량/이평선/지지저항 점수 계산 분리
  - 진입 금지 조건을 `can_enter()` 최상단에서 우선 처리
  - 구조 기반 청산/익절 판단 추가

- `core/heartbeat.py` 리팩토링
  - 기존 `recent_low + effective_gap` 매수 트리거 제거
  - 기존 `peak - trailing_pct` 단순 trailing 청산 제거
  - `can_enter()`와 `should_exit()` 결과를 사용하는 상태 머신으로 변경
  - 진입 시점의 저점/고점/peak를 상태에 저장해 구조 붕괴 판단에 사용

- `run.py` 수정
  - 구조 전략 설정을 `StructureConfig`로 주입
  - 매 tick마다 복기 가능한 전략 판단 로그를 `strategy.log`에 기록

- `core/config.py`, `config.yaml` 수정
  - `strategy_log_path`
  - `structure_min_candles`
  - `structure_short_ma_window`
  - `structure_trend_window`
  - `structure_tolerance_pct`
  - `structure_min_avg_volume`
  - `structure_max_spread_pct`
  - `structure_amplitude_pct`

### 테스트
- `tests/test_market_structure.py` 신규 추가
- 테스트 케이스:
  - 하락 중 휴식: `FALLING_SIDEWAYS`, 진입 금지
  - 축적형 횡보: `ACCUMULATION_SIDEWAYS`, 감시 상태
  - 진입 허용: `HEARTBEAT`, 진입 허용
  - 구조 붕괴: 즉시 청산
  - 과열 구간: 신규 진입 금지, 익절 준비/익절

### 검증 결과
- `python -m compileall core run.py tests` 통과
- `python -m unittest tests.test_market_structure -v` 통과
- `python run.py --mode demo --ticks 12` 실행 통과

## 실전 운용 전 보완 패치

### 목적
- tick 하나를 candle로 착각하지 않도록 `tick -> candle aggregation -> closed candle 판단` 흐름으로 변경했다.
- 애매한 횡보와 단독 저항 터치 익절을 보수적으로 처리했다.
- 최소 투자금액 guard를 config와 CLI override로 지원했다.

### 주요 변경
- `core/candle_aggregator.py` 신규 추가
  - interval 단위 OHLCV candle 생성
  - bucket 전환 시 이전 candle을 `closed`로 반환
  - price/interval 유효성 검증 추가

- `core/heartbeat.py`
  - `on_candle()` 추가
  - live/demo 경로는 closed candle 기준 판단으로 전환
  - `on_tick()`은 legacy fallback으로 유지

- `run.py`
  - `CandleAggregator`를 runtime에 포함
  - demo stream이 volume을 함께 전달
  - live callback이 `(price, timestamp, volume)` 시그니처를 지원
  - `min_trade_cash` guard 추가
  - `--min-trade-cash`, `--min` CLI override 추가

- `exchanges/coinone/ws.py`
  - Coinone WebSocket price callback을 volume 포함 형태로 변경
  - TRADE payload volume 후보 키 파싱 추가

- `core/market_structure.py`
  - `classify_sideways()` 충돌 시 `FALLING_SIDEWAYS` 우선
  - `should_exit()`에서 hard exit은 1개 조건 즉시 청산, 익절은 2개 이상 조건 필요

### 테스트
- `tests/test_candle_aggregator.py` 추가
- `tests/test_run_guards.py` 추가
- `tests/test_market_structure.py` 보강
- 검증:
  - `python -m compileall core exchanges run.py tests`
  - `python -m unittest discover -v`
  - `python run.py --mode demo --ticks 120 --min-trade-cash 100`

### 운영 메모
- 현재 candle 진행 중 값은 판단에 쓰지 않고, closed candle만 전략 평가에 사용한다.
- live volume 정확도는 Coinone `TRADE` payload의 실제 volume 필드 제공 여부에 의존한다.
- `datetime.utcnow()` deprecation warning은 demo timestamp 생성부에서만 발생하며 실행에는 영향 없다.

## CLI 실행 표시 개선

### 목적
- demo 실행이 정상 처리돼도 콘솔 출력이 없어 실행되지 않은 것처럼 보이는 문제를 개선했다.
- demo가 batch 시뮬레이션처럼 즉시 종료되는 문제를 수정해 기본 실행은 상주 모드로 변경했다.

### 변경
- `run.py` demo/live 시작 시 `[RUN]` 출력 추가
- demo 완료 시 `[DONE]` 요약 출력 추가
- 로그 파일 위치를 `[LOG]`로 출력
- demo timestamp 생성부의 `datetime.utcnow()` deprecation warning 제거
- `python run.py --ticks 120 --min-trade-cash 100`은 계속 실행된다.
- 1회성 검증 실행은 `--once`를 붙여 `python run.py --ticks 120 --min-trade-cash 100 --once`로 실행한다.

### 검증
- `python -m compileall run.py`
- `python run.py --ticks 12 --min-trade-cash 100 --once`
- `python -m unittest discover -v`
