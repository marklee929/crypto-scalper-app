# Codex 작업 프롬프트

프로젝트명: **Heart Beat Coin Scalper**

목표: 기존 코인 스캘퍼를 단순 퍼센트 매매가 아니라, **구조 기반 상태 판별형 스캘퍼**로 리팩토링한다.

핵심 원칙은 다음과 같다.

> 가격이 싸졌다고 매수하지 않는다.
> 구조가 살아 있을 때만 진입한다.
> 진입보다 진입 금지가 더 중요하다.
> 손절/익절은 단순 퍼센트가 아니라 구조 붕괴/저항 도달 기준으로 판단한다.

---

## 1. 작업 범위

현재 프로젝트에 아래 개념을 반영한 전략 모듈을 추가하거나 기존 전략 모듈을 리팩토링한다.

구현 대상:

1. 시장 상태 분류기
2. 구조 점수 계산기
3. 횡보 판별기
4. 진입 금지 필터
5. 진입 허용 조건
6. 구조 기반 청산 조건
7. 복기 가능한 로그 출력

---

## 2. 핵심 상태 정의

시장 상태는 최소 아래 5개로 분류한다.

```text
DEAD
FALLING
ACCUMULATION
HEARTBEAT
STRONG_HEARTBEAT
```

각 상태 의미:

```text
DEAD:
거래량 부족, 고점 하락, 저점 하락, 이평선 아래, 반등 약함.
매매 금지.

FALLING:
큰 하락 후 횡보, 반등 약함, 이평선 회복 실패, 저점 갱신 가능성 있음.
하락 중 휴식. 매매 금지 또는 관망.

ACCUMULATION:
하락 후 저점 유지, 저점이 조금씩 높아짐, 하락 거래량 감소, 반등 고점 상승 시도.
축적 후보. 아직 매수 확정 아님.

HEARTBEAT:
저점 상승, 고점 상승, 단기 이평선 회복, 상승 거래량 증가.
진입 허용 후보.

STRONG_HEARTBEAT:
HEARTBEAT 조건에 더해 직전 저항 돌파 또는 저항 맞고 가격 유지.
진입 가능성이 가장 높은 상태.
```

## 3. 점수 계산 기준

아래 기준으로 구조 점수를 계산한다.

```text
structure_score:
- 저점 상승: +2
- 고점 상승: +2
- 저점 유지: +1
- 고점 하락: -2
- 저점 이탈: -4

volume_score:
- 상승봉 거래량 증가: +2
- 하락봉 거래량 감소: +2
- 하락봉 거래량 증가: -3
- 거래량 급감: -1

ma_score:
- 단기 이평선 회복: +2
- 단기 이평선 위 유지: +1
- 이평선 아래 눌림: -2
- 데드크로스: -3

support_resistance_score:
- 직전 저항 돌파: +3
- 저항 맞고 가격 유지: +2
- 저항 맞고 급락: -3
- 직전 지지 이탈: -4
```

총점 기준:

```text
score <= -5: DEAD
-4 <= score <= 0: FALLING
1 <= score <= 4: ACCUMULATION
5 <= score <= 8: HEARTBEAT
score >= 9: STRONG_HEARTBEAT
```

단, 예외 규칙이 점수보다 우선한다.

## 4. 예외 규칙: 진입 금지 조건

아래 조건 중 하나라도 만족하면 점수와 무관하게 진입 금지한다.

```text
- 직전 저점 이탈
- 고점이 계속 낮아짐
- 이평선 아래에서 횡보
- 하락 거래량 증가
- 저항 맞고 큰 음봉
- BTC 급락 중
- 스프레드 과다
- 거래량 부족
- 신규 상장 첫날
- 뉴스/서사 급등 직후 추격 구간
```

이 필터는 반드시 `canEnter()` 또는 동등한 진입 판단 함수의 최상단에서 처리한다.

---

## 5. 횡보 판별 로직

횡보는 반드시 두 가지로 나눈다.

```text
ACCUMULATION_SIDEWAYS
FALLING_SIDEWAYS
```

### ACCUMULATION_SIDEWAYS 조건

다음 중 3개 이상 충족하면 축적형 횡보로 본다.

```text
- 저점이 낮아지지 않음
- 저점이 조금씩 높아짐
- 반등 고점이 조금씩 높아짐
- 하락 거래량 감소
- 상승 거래량 증가
- 단기 이평선 회복
- 저항을 여러 번 두드림
```

### FALLING_SIDEWAYS 조건

다음 중 3개 이상 충족하면 하락 전 대기형 횡보로 본다.

```text
- 저점은 겨우 유지
- 고점은 낮아짐
- 반등 거래량 약함
- 하락 거래량 증가
- 이평선 아래에서 눌림
- 저항 재도전 실패
```

FALLING_SIDEWAYS는 진입 금지 상태로 처리한다.

---

## 6. 진입 조건

진입은 아래 조건 중 3개 이상을 만족해야 한다.

```text
- 저점 상승 또는 저점 강한 유지
- 반등 고점 상승
- 단기 이평선 회복
- 하락 거래량 감소
- 상승 거래량 증가
- 저항 돌파 후 가격 유지
```

권장 진입 형태:

```text
1차 진입:
ACCUMULATION → HEARTBEAT 전환 시 소액 진입

2차 진입:
직전 저항 돌파 후 눌림에서 저점 유지 확인 시 추가 진입
```

금지 진입 형태:

```text
- 저항 바로 아래 추격 매수
- 하락 중 횡보 매수
- 거대양봉 꼭대기 매수
- 단순 -10% 하락 매수
```

## 7. 청산 조건

청산은 퍼센트만으로 처리하지 말고, 구조 붕괴 기준을 우선한다.

청산 조건:

```text
- 진입 근거였던 저점 이탈
- 단기 이평선 재이탈
- 하락 거래량 증가
- 고점 갱신 실패
- 저항 도달 후 상단 꼬리 증가
- 저항 맞고 급락
- BTC 급락 동조
```

익절 조건:

```text
- 직전 저항 도달
- 단시간 과열 급등
- 상단 꼬리 증가
- 상승 거래량 감소
- 고점 갱신 실패
```

손절 조건:

```text
- 진입 구조 붕괴
- 직전 저점 이탈
- 단기 이평선 재이탈
- 하락 거래량 증가
```

## 8. 10% 전략 재정의

기존 방식은 제거한다.

```text
-10%면 매수
+10%면 매도
```

새 방식:

```text
10%는 매수/매도 트리거가 아니라 시장의 기본 진폭으로만 사용한다.
```

사용 방식:

```text
- 10% 안에서 진입 타이밍 조절
- 10% 안에서 빠른 익절/보유 판단
- 10% 안에서 손실 폭 제한
- 10% 초과 움직임은 과열 또는 붕괴 상태로 별도 판정
```

## 10. 의사코드

```python
def classify_market(candles, btc_state=None):
    if has_no_trade_condition(candles, btc_state):
        return "NO_TRADE"

    structure_score = calc_structure_score(candles)
    volume_score = calc_volume_score(candles)
    ma_score = calc_ma_score(candles)
    sr_score = calc_support_resistance_score(candles)

    score = structure_score + volume_score + ma_score + sr_score

    sideways_state = classify_sideways(candles)

    if sideways_state == "FALLING_SIDEWAYS":
        return "FALLING"

    if score <= -5:
        return "DEAD"
    elif score <= 0:
        return "FALLING"
    elif score <= 4:
        return "ACCUMULATION"
    elif score <= 8:
        return "HEARTBEAT"
    else:
        return "STRONG_HEARTBEAT"
```

```python
def can_enter(candles, btc_state=None):
    if has_no_trade_condition(candles, btc_state):
        return False

    state = classify_market(candles, btc_state)

    if state not in ["HEARTBEAT", "STRONG_HEARTBEAT"]:
        return False

    confirmations = 0

    if higher_low(candles) or strong_low_hold(candles):
        confirmations += 1

    if higher_high(candles):
        confirmations += 1

    if recovered_short_ma(candles):
        confirmations += 1

    if sell_volume_decreasing(candles):
        confirmations += 1

    if buy_volume_increasing(candles):
        confirmations += 1

    if resistance_break_and_hold(candles):
        confirmations += 1

    return confirmations >= 3
```

```python
def should_exit(position, candles, btc_state=None):
    if btc_state == "DUMPING":
        return True

    if broke_entry_structure(position, candles):
        return True

    if broke_previous_low(candles):
        return True

    if lost_short_ma(candles):
        return True

    if sell_volume_spike(candles):
        return True

    if failed_to_make_new_high(candles):
        return True

    if strong_rejection_at_resistance(candles):
        return True

    return False
```

## 11. 로그 출력 요구사항

각 판단은 반드시 복기 가능하게 로그를 남긴다.

예시:

```text
[SCAN] symbol=ARB state=ACCUMULATION score=4 structure=1 volume=2 ma=1 sr=0 reason=low_hold,sell_volume_down
[WAIT] symbol=ARB reason=lower_high_below_ma state=FALLING_SIDEWAYS
[ENTER] symbol=OP state=HEARTBEAT score=7 reason=higher_low,ma_reclaim,buy_volume_up
[NO_TRADE] symbol=S reason=broke_previous_low
[EXIT] symbol=OP reason=structure_break prev_low=0.022 entry=0.023
[TAKE_PROFIT] symbol=OP reason=resistance_touch level=0.025
```

로그에는 최소 아래 정보가 포함되어야 한다.

```text
symbol
state
score
각 세부 점수
진입/대기/청산 사유
기준 가격
현재 가격
이전 저점
이전 고점
저항/지지 레벨
```

## 13. 구현 시 주의사항

1. 기존 자동매매 코드에 단순히 `-10% buy`, `+10% sell` 구조가 있다면 제거하거나 비활성화한다.
2. 진입 금지 필터가 항상 최우선이다.
3. 상태 판정 결과가 애매하면 매수하지 않는다.
4. 데이터 부족 시 매수하지 않는다.
5. 로그는 나중에 전략 복기를 위해 자세히 남긴다.
6. Coinone API는 최신 기준 v2.1을 우선한다.
7. 수익 극대화보다 손실 최소화를 우선한다.
8. 신규 상장/뉴스 급등/저유동성 코인은 기본 제외한다.
